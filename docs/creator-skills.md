# 设计与口播：第一轮创作能力

这一轮把两种可独立使用的能力接入已有 Chat：单双色封面设计和口播优化。仍由同一个 Hermes Agent 执行，结果留在聊天历史中；修图、画布继续独立使用。

## 使用入口

更新代码后运行：

```powershell
.\scripts\miniclaw.ps1 prepare
.\scripts\miniclaw.ps1 build
.\scripts\miniclaw.ps1 web
```

如果服务已经运行，先关闭旧服务再启动；前端刷新。`prepare` 安装完整的内置技能包，包括设计目录、说明和许可，不需要在界面逐个导入 JSON。

在 Chat 输入框点击“选择技能”：

| 技能 | 输入 | 输出 | 条件 |
|---|---|---|---|
| 口播优化 | 本轮事实、原稿、想保留的句子、时长或语气 | 主稿、两种开头、3–5 个简单镜头、待核对项 | 文本流程，无执行工具依赖 |
| 单双色封面设计 | 主题、准确标题、比例、已知商品事实 | 配色与构图方案、可复制提示词、画布建议 | 完整配套资料，当前 Agent 已加载 `skill_view` |

设计技能不可用时，在“设置 → 工具”选择“让模型查阅技能”，保存后新建对话。工具选择影响新 Agent，已打开的旧对话不会自动得到新权限。安装技能或保存依赖也不会自动启用工具。当前工具设置由用户管理，接入没有永久修改它。

## 一次可以动手的练习

先选择“口播优化”，发送：

> 这是虚构练习商品，已知只有 360mL 陶瓷杯、没有品牌。把这段话改成约 20 秒自然口播，保留“每天一杯，慢一点”：这个杯子保温12小时，绝不烫手，我用了一个月特别好。保温、温度和个人体验都没有证据，请删除这些宣称，给两种开头和简单分镜。

然后选择“单双色封面设计”：

> 用同一虚构商品设计 3:4 封面，标题严格为“每天一杯，慢一点”。读取技能配套资料，列出实际配色、构图、字体角色 ID 和准确色值，给提示词与画布排版建议。不出图。

最后换成自己的商品事实和照片，在现有图片工作区明确执行修图，比较候选后采用。准确标题与容量用画布的文字层排版，再导出。没有照片时，设计方案只是文字方向，不能当作已确认的商品外观。

设计 Skill 本身不调用图片服务。当前 Qwen Provider 是需要源图的图片编辑，不是文生图；复制提示词也不会自动产生图片任务。口播 Skill 不生成音频、视频或真实字幕时间轴。录制后再从剪辑工具取得真实视频与 SRT。

模型输出仍需要人工核对：标题是否逐字正确，数字是否有来源，“未验证”是否被写成“没有该能力”，主观描述是否冒充个人体验，提示词是否误要求烘焙中文文字。技能说明引导模型，工具权限和程序校验才是执行边界；文本规则不是事实准确性的保证。

## 这次值得学习的实现

- `skills/mono-color/`：适配入口、MIT 设计方法摘要、六份上游 JSON 目录、原许可和固定版本来源。不含上游示例作品。
- `skills/spoken-script/SKILL.md`：无工具依赖的录制前文本流程。
- `miniclaw_web/bundled_skills.py`：明确列出包内文件，安装缺项，保留本地修改；检查设计资源是否存在、JSON 可解析且版本为 1。
- `miniclaw_web/runtime.py` 与 `frontend/src/skill-readiness.ts`：只有正文匹配已核对版本、资源可读、当前 Agent 的实际工具满足依赖，才允许提交。资源缺失显示原因并在后端拒绝。

`prepare` 不覆盖已存在的文件。相同内置正文的包可补齐缺失资料；正文已被改过就不混入新版配套文件。修改已有目录后不会自动恢复原文件；需要自己核对或备份后恢复。内置正文升级也需要按现有技能编辑/依赖核对流程处理，避免覆盖用户修改。

这是一套固定技能包安装，不是通用 GitHub 插件安装器。界面仍只导入单个 `SKILL.md`；其他带脚本或资源的外部技能不能据此宣称完整安装。

## 验证与后续

```powershell
# 自动检查，不调用模型
.\scripts\miniclaw.ps1 test

# 服务已运行时检查两项实际绑定，不调用模型
.\.venv\Scripts\python.exe scripts/verify_creator_live.py

# 可选：两次配置模型调用，使用虚构资料，恢复原工具选择
.\.venv\Scripts\python.exe scripts/verify_creator_live.py --model
```

真实模型验收核对资源读取、标题与色值、口播没有工具调用、成果记录保存；报告和原文留在被 Git 忽略的 `.codex/verification/`。自动通过不表示文案已达到可发布品质。
