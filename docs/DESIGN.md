# 界面设计约定

## Chat 附件卡（2026-10-11）

- 用户指定 Codex 的附件预览卡作为布局参考。Composer 与已发送用户消息统一使用紧凑 tile：上部图片缩略图或文件图标与格式、底部单行文件名；草稿右上可移除，已发送消息保留阅读入口。沿用暖纸、石墨与柿橙变量，文档图标不冒充 PDF 首页预览。
- 正常可用的卡片省去常驻大小和操作列表；等待、解析中、部分可读取、失败仍显示文字状态，并关联可访问说明。点击文档打开详情，点击图片沿用完整图片预览。完整文件名、大小、来源警告、下载与手动重试在详情里保留。
- 桌面输入区最多四项一排，窄屏每项128px；多附件换行，输入区附件最大272px后独立滚动。用户历史附件与正文靠右对齐并随对话滚动；图片的原编辑/加入画布动作在卡片下方独立操作条保留，不能因改tile丢弃。助手产物与导演独立附件入口继续使用原row变体及原操作。
- 详情为可关闭的原生 dialog，正文在低高度窗口独立滚动，标题与下载/重试固定；Esc、背景或关闭按钮关闭后恢复触发卡片焦点。处理页数不等于无缺口页数，服务只返回部分警告时说明精确总数。
- 交互沿用140–200ms反馈并尊重减少动态效果。移除或切换归属后，迟到重试/下载回执不能恢复已移除附件或影响新附件状态；状态刷新只能更新草稿中仍存在的引用。

尺寸为本轮实现选择，已检查桌面、窄屏与低高度布局；用户尚未对新视觉作最终验收。记录见 `.codex/verification/attachment-ui-2026-10-11/README.md`。

## Chat 轨迹（2026-10-11）

- 用户指定 DeepSeek Harness 截图作为轨迹布局参考。Chat 标题下设“对话 / 轨迹”，不新增顶级工作区；轨迹与消息输入共用当前会话。
- 轨迹采用顶部三轨时间线、紧凑步骤列表、按需打开的右侧详情。详情概述 / 预览 / 原始内容均只读；搜索、状态筛选和时间线选择联动，不重新执行步骤。
- 默认“对话顺序”：用户输入开始一轮，绿色应用上下文、公开助手、工具与恢复按实际事件顺序排列，任务收尾在本轮末尾；成功模型的相同公开输出不重复成一行。模型指标及完整请求通过对应助手详情和时间线查看；“全部事件”保留所有物理请求。列表标序号 / 输入轮次 / 实际时间，不以更新时间重排对话。
- 应用上下文由明确拼接入口记录，绿色标签与正文表示可见的注入内容；不把上下文混进用户原话，旧数据不补造。类型色以绿色上下文、蓝色用户、紫色助手/模型、柿橙工具区分，失败仍配文字。
- 沿用最新暖纸 / 石墨 / 柿橙变量与中文系统字体。类型色只区分输入、模型、助手、工具、恢复与任务；失败和待核对同时提供文字，不仅靠颜色。
- 详情桌面360px、较窄桌面320px，窄屏变为可关闭抽屉。列表和详情独立滚动，长参数和JSON在详情内换行，不撑宽页面。
- 未记录的耗时、轮次与用量不推算；历史对话按已保存步骤回放，模型请求与实际工具执行分别统计。复用回执或等待确认不增加执行次数。
- 视图切换淡入、选中行反馈、详情展开动效沿用140–200ms节奏，尊重减少动态效果。切视图不卸载Composer，不丢草稿与原对话阅读位置。
- 加载当前会话时显示读取提示，完成前不下空结论或显示零次数。总任务跨度在列表末尾收尾，不能覆盖三泳道的实际请求间隔；可见记录数与原始事件数分别统计。
- 概述先给关键状态、尝试、耗时与用量，工具结果 / 参数优先；来源、轮次、开始时间及工程ID在关联记录后置。窄屏默认首屏必须能看到公开结果，不用重复名称和格式化JSON空行挤掉结果。

## 当前规范（2026-10-09 用户六图反馈纠正）

以下规范取代后文早期方案。用户明确否定 Agent 新增的固定右侧属性栏与 Chat 顶部画布记录卡片；前一轮工程检查不能视为视觉验收。延续 Claude 的暖纸 / 柿橙方向，恢复围绕画布节点编辑的操作。具体尺寸仍是 Agent 实现选择，未获用户最终审美验收。

- 全产品共用 `frontend/public/studio/tokens.css`：暖纸色面板、暖灰画布、石墨文字、柿橙色主动作与选中态。连线使用独立 `--ui-connection`，默认线与背景约 3.5:1；选择不改变路径。
- 桌面顶栏 52px，左素材栏 248px / 收起 44px。节点编辑位于画布内节点旁，收起440px、展开640px，受实际可用宽度约束；和底部工具栏保留16px间距。右侧只有用户主动打开的440px助手。菜单贴触发按钮8px，按可用空间翻转和滚动。
- 图片选中时显示修图、精细编辑、生成视频和更多；下载、素材库、来源、版本与删除收进更多。提示词、模型和生成围绕当前节点，不在右侧重复大预览。普通选中不移动画布；显式展开或定位参考图必要时调整视野，避免编辑器盖住当前产品。完整精修与正式版本链保留。
- 镜头任务状态放在节点标题旁，用“待核对 / 已采用”等简短文字；完整状态和规格保留在悬停说明中，预览图片上不叠加状态标签。
- 完整片段编辑以提示词为主区，按弹窗剩余高度伸展；名称与时长的标签、42px 控件对齐。示例、镜头运动和保留要求默认折叠，展开后并排组织；保存操作固定在底部。低高度窗口允许正文滚动，不能裁掉辅助项或保存按钮。
- 项目资料的共同要求与镜头为主区，生成次数与最近变更在侧区；输入用暖纸色、细边框，保存上限与返回画布用橙色。正文和编辑文字 14px，辅助信息 12–13px，名称可换行。
- Chat 是主入口，画布助手和完整对话共享同一会话。图片和修图结果可直接加入当前项目，不复制文件；来源链接只使用已有消息 ID。Chat 正文不插入原始保存日志卡片；保存记录仍在项目资料中。失败保留输入，待保存草稿不会被刷新覆盖。
- 项目侧栏只有一个聊天入口，不设“讨论 / 修图 / 优化提示词”模式页签。输入框上方显示本轮可预览、可移除的画布引用；点击画布对象追加引用，上传或粘贴图片补充材料，不提供聊天对象下拉框。草稿与上传图片按项目保存，增加引用不切换会话或清空输入。普通问题按意图回复，不默认改写提示词；保留打开聊天时的当前图片与方案、候选、精细修图流程的关联，追加参考不替换它；移除当前引用解除关联。多项引用是阅读资料，镜头输入图不默默成为修改对象；服务器按归属/版本读取真实图片，并保存每条消息的不可变引用快照。
- 提示词优化在选中节点的编辑器内比较原文与建议、续改、采用，再回到原位生成。复用唯一会话连接，关闭仅隐藏，不重建对话；隐藏状态收到迟到回执不能自动重新打开。讨论与优化文字草稿分开恢复，附件仍按原会话与节点归属；忙碌切换和采用前目标版本检查保留。窄屏编辑器与内嵌优化需一起覆盖素材栏，低高度表单可滚动。
- Chat 手动选择的技能在当前对话内持续使用，发送成功只清除已发送文字与附件；技能由用户移除或切换。选择随对话草稿恢复，新对话不继承其他对话的技能；输入标签显示“持续使用”。
- Chat 用户消息保留原始分点换行与空行。附件在正文上方，与正文共用右侧消息宽度；技能名称用独立的中文说明显示。不能用会话标题的一行预览替代正文，也不能按数字猜测并改写用户分点。
- 画布助手沿用 Chat 的段落与列表阅读节奏，正文14px、方案步骤13px；长提示词、内联代码、工具结果与方案参数均在侧栏内换行，参数默认折叠。表格只在自身横向滚动，不撑宽对话。回答输出只跟随停留在底部的用户；查看历史时保留位置，并提供回到最新消息。
- 画布助手输入支持上传、粘贴和拖入对比/圈选截图，最多4张、单张5 MiB。预览在文字上方，附件区高度受限；按会话、项目、节点恢复草稿，切换节点不搬移图片。发送失败保留图文，成功只清理已发内容。以活跃会话的真实看图能力决定能否发送，不能只给模型图片编号却声称看见画面；反馈图不默认替换工作图或触发生成。
- 修图方案与结果归到产生它们的回复下，继续讨论时不移到末尾；无法关联的旧记录收进上下文历史。模糊反馈先问1–3个普通用户能理解的问题，支持选项和自由回答，失败保留答案。整图AI方案由用户点击“回填画布，选择模型”，保存要求后展开节点编辑器，保留当前模型，在画布明确生成；局部选区和混合步骤仍走精细修图，不默默扩大修改范围。关闭助手后按实际画布宽度摆放图片和编辑器。
- 从 Chat 建立画布默认带入原方案、镜头与该方案之前上传的图片，可取消带图。空镜头直接提供“选择首帧”，在当前位置选画布素材或本项目对话的图片并自动连线；首帧更换不切换到多图参考模式。图片和镜头的语义对应由用户选择，可先修图后选用；带入方案和图片不会触发生成。
- 桌面优先。窄屏只维持可使用的回退布局，手机体验仍留后续专项调整。动效复用 140–200ms 透明度/位移动效，并尊重减少动态效果设置。

前一轮固定属性栏和画布记录卡片已被用户否定。本轮实际操作和画面复查见改版手册最新条目；未替用户宣称审美验收通过。历史段落只保留为演进记录。

用户在 2026-10-08 要求：做 UI 时使用 oil-ui-pro，改进信息排版、布局和尺寸，减少粗糙的模板感。此次已将技能升级为官方 0.17.0。

后续 UI 修改先读取已安装的 oil-ui-pro，并基于真实内容、桌面与窄屏截图检查。避免仅凭源码宣称视觉效果通过。

## 项目资料

沿用深色画布、中文系统字体和浅蓝选中标记。项目名称是顶部主信息，保存状态只表达一次；内容在正文滚动，顶部身份、分类和底部操作保持可见。

- 桌面：共同要求和镜头与生成设置、近期记录并列；设置区内显示剩余次数、已预留与总上限，输入和保存按钮就近排列。
- 窄屏：按共同要求、镜头、次数设置、近期记录、备份顺序阅读。共同要求随内容展开，避免文本框和正文同时滚动。镜头名称和状态分两行，保留完整状态。
- 名称和区域标题采用 14px，正文采用 14px，操作采用 14px，辅助信息采用 12–13px。手机文字输入使用 16px，避免移动设备聚焦时自动缩放；项目标题使用 20–22px。
- 长名称允许换行；保留错误原因、次数范围、失败任务的计数规则。备份折叠展示，不以旧备份表达当前保存失败。

本轮依据用户标注进行了局部整理，未调整全产品字体和配色。用户尚未对新视觉作最终验收。

## 对话与画布（2026-10-09）

用户授权按 Claude 方案 B 调整：Chat 是主入口，保留通用 Agent 能力；画布助手与完整对话共享项目原有会话。项目列表是辅助入口，每个项目继续关联一个会话。

本次采用以下设计规则（具体尺寸、色值为 Agent 推断，待用户视觉验收）：

- 全产品主要创作界面共用 `frontend/public/studio/tokens.css` 的炭灰底色、浅蓝动作色、中文系统字体。正文 14–15px，辅助信息 12–13px，手机输入 16px。
- 节点编辑默认展示两行提示词摘要，用户展开后编辑；桌面摘要宽 360px、展开宽 440px，按可用空间收窄。选中节点时不自动平移，展开时按遮挡情况调整视野。
- 底部仅一条工具栏；手机节点纵向排列，隐藏失去空间意义的连线与缩放控制，保留添加和撤销。
- 原始文件名仍保存在数据中；长哈希名称只在显示时转为“图片 N”。创意卡片显示去掉 Markdown 标记后的摘要，完整内容在备注编辑中保留。
- 画布顶栏只有一个“助手”入口，助手顶部只有一个“完整对话”入口。模型菜单贴近触发按钮，空间不足时翻转和内部滚动。
- 对话 `/c/:session`、画布 `/p/:workspace`、项目列表 `/projects`。旧查询参数链接继续可读，旧编辑器通过显式 `?module=canvas` 或 `?module=creator` 访问。

### 澄清问题面板（2026-10-09 修订）

- 待回答时问题面板承载答案，普通输入框保留用于明确取消、修改需求和换话题（2026-10-11 补充）。题目为主信息，编号选项一行一项，“其他，自己填写”按需展开；不默认选中、不点击选项即自动提交。简短问题答案仍通过面板提交，不把普通输入自动当成答案；含混输入保留草稿并提示归属。
- 多题逐题切换并保留答案，整组一次提交。页脚只强调“回答并继续”，修改需求与取消为次级文字操作。问答提交为局部例外，采用现有 ink 墨色以保持克制；生成、保存与采用动作沿用原主动作色。使用 ui-surface、ui-raised、ink、line 暖色变量，不混入白色表单默认值。
- 已完成、已取消和已修订的问题不常驻输入区，答案只留在聊天记录；恢复排队只用一行提示。过期与待核对保留轻量操作提示，失败保留答案与当前题目。
- 选项42px以上、正文14px、题目15px，窄屏自由输入16px；面板在低高度窗口内部滚动。动效尊重减少动态效果设置。

### 聊天图片预览（2026-10-09）

- 点击图片附件在当前页面打开全屏深色预览浮层，初始完整适配窗口；文件名和关闭入口在顶部，缩放、适应窗口和下载在底部。预览不跳转地址或新开标签页。
- 支持按钮、滚轮和双击缩放，放大后拖动查看；Esc、关闭按钮及点击空白背景关闭，恢复缩略图焦点和原阅读位置。沿用原附件像素，不重新上传、不触发生成。
- 桌面和390px窄窗口保持图片完整与操作栏可用；100%表示相对适配窗口尺寸。视觉已经实际检查，未做独立设计评分。

### 助手提问与内部上下文（2026-10-09）

- 用户消息气泡只显示本次实际输入的问题，技能名称单独显示；操作规则、提示词快照和项目事实由后台提供给模型，不拼进用户可见正文。前端引用已有项目与目标，后台读取经过会话关联和版本核对的真实资料。
- 续改时未采用的建议与上一轮目标作为隐藏参考传递，不覆盖本次问题。仅对旧版自动包装的已知模板还原提问，用户自己写的文字和JSON保持原样；不改写历史模型输入或数据库正文。
- 完整对话与内嵌助手共用显示规则；复用消息只复用实际问题。事实随保存版本更新，模型服务端的token缓存机制另行处理。
