# 上下文加载与压缩实战

通过“设置 → 开发者 → 上下文诊断”打开学习与排查面板。它复用 Hermes 的 `session.context_breakdown`，分类 token 是估算；总用量保留后端来源标记。`provider_usage_plus_estimate` 表示真实用量锚点加新增内容估算，不能当成完全精确的计费数。

## 用户输入到模型请求

用户输入 → 程序组装 system、模型历史、当前 user 和工具 schema → 模型返回文字或 tool_calls → 程序校验、执行 → 回填 tool 结果 → 再次调用模型 → 回答或达到停止条件。模型提出调用，不会自己执行 Python。

恢复旧聊天时，`session.resume` 读取数据库，和把网页聊天气泡直接重新发送不同：

1. `hermes_state_messages.py:get_resume_conversations` 查当前会话与压缩关联链；查询条件包含 active 或 compacted。
2. 模型历史只保留当前会话 active 消息；展示历史保留归档正文并消除压缩代数重复。
3. `agent/replay_cleanup.py:canonicalize_replay_history` 校正工具调用与结果序列。
4. `agent/conversation_loop.py:_restore_or_build_system_prompt` 判断能否复用会话引用的旧提示词，否则构建新的提示词。
5. 在模型接口转换与发送前，还可能附加本轮上下文、压缩历史；数据库恢复结果并不是完整 API 请求快照。

这属于程序按状态与协议筛选，当前没有语义检索历史。工具筛选是另一条链：启动器读取明确工具集配置 → Hermes 注册和环境检查 → 模型工具定义组装 → 模型自行决定调用什么 → 程序检查调用是否合法。观察面板的工具名称来自实际 `session.info`，不是磁盘上所有工具文件的名单。

Skills还需区分安装、启用、自动索引与显式加载。本机可管理51项已启用技能，但仅开放文件工具，系统提示词不会自动注入技能工具索引。输入框选择技能后，发送时通过原生 `command.dispatch` 展开正文再提交模型；聊天和持久化展示使用上游技能投影，不展示完整流程文本。选择技能不会增加工具权限。

## 看实际恢复内容

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/inspect_context.py 20261002_192027_92ec2b --full --output .codex/verification/context-full.json
```

这是只读检查，报告中包括提示词正文、清理后模型历史、当前会话各行是否被选入。`--full` 会将本地会话正文写入报告，分享前自行检查内容。默认省略正文。脚本调用上游真正的恢复函数，不复制其筛选算法；报告不会提交模型。

本次检查该会话：数据库当前会话14条，模型恢复14条，清理后14条，展示转换前14条，提示词21,733字符，没有压缩摘要。空正文的助手工具调用正常保留。

## 压缩做什么

当前固定上游的默认引擎是 `ContextCompressor`，入口见 `agent/context_compressor.py:compress`：

1. 判断消息是否足够；先裁剪允许清理的旧工具结果与空回声。
2. 划分保护开头、可摘要区间、近期保留区间。保留区间受到 token 预算、用户轮次、工具配对约束，不能简单等同于“永远保留最后20条”。
3. 摘要模型处理旧区间，保留约束、事实、任务进展和必要标识。已有摘要参与后续摘要；摘要默认有损。
4. 组装保留开头＋摘要或摘要承载消息＋近期历史，并做结构和进展检查。失败、没有可摘要区间或会增长时可能返回不变/中止。
5. Agent 与持久化层提交结果；通过活动状态、归档标记或关联会话链支持恢复和旧聊天展示。不同压缩路径的写库方式应以实际记录验证。

自动触发与手动压缩是两回事。Agent 的默认比例为50%，还受输出预留、小窗口保护、绝对 token 上限和配置影响；不能直接用“窗口×50%”推断本机唯一触发点。消息网关还有另一层85% session hygiene；miniclaw 使用的是 TUI gateway，不能把消息网关的整条链套到 Web 上。

DS 的长窗口使自然聊到自动阈值更费时间，但不会阻碍手动演示。不要为了演示把实际模型窗口配置伪造得很小；先用隔离的教学会话或离线夹具观察结构，再验证真实摘要。

## 两种演示

零模型费用的结构演示：

```powershell
.\.venv\Scripts\python.exe scripts/demo_compression.py
```

它调用真实 Hermes 压缩器，窗口设为1,000,000；教学夹具把开头/尾部保护数量及尾部预算调小，摘要 LLM 被明确替换成固定文字。结果保存在 `.codex/verification/compression-demo.json`，包含完整 before/after。

本次结果：50条→6条，历史估算24,411→2,201 tokens，调用摘要替身1次。它验证消息选择与摘要安装，不验证模型摘要质量、真实 API 用量或数据库压缩提交。

真实演示：在单独教学会话积累多轮资料，打开上下文面板，填摘要重点，点击“手动压缩当前会话”。调用的是已有 `session.compress`，可能产生费用；结果显示消息数、token估算、no-op/中止/回退信息。完成后通过持久化ID重新运行 inspect_context 查看摘要与 active/compacted，再追问前面的约束，检验模型保留了什么。短会话可能无变化，这是有效结果。

本次没有对已有用户会话执行真实模型压缩。已完成构建、4项前端测试、真实页面分类/文件/工具观察、只读恢复检查及离线结构演示。完整模型请求捕获和真实 DS 摘要持久化验收仍待专用教学会话验证。
