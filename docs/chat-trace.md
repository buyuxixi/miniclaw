# Chat 轨迹视图

2026-10-11。用户指定 DeepSeek Harness 的轨迹页面作为布局参考。MiniClaw 在同一 Chat 会话中增加“对话 / 轨迹”：顶部按时长、轮次或调用顺序显示输入 / 模型 / 工具时间线，下方是步骤列表，选中后右侧显示概述、预览和脱敏原始记录。保留本产品的字体、暖纸底色和动作色。

进入任意对话，点击标题下“轨迹”；默认按“对话顺序”阅读用户输入、绿色应用上下文、助手、工具与恢复事件，每轮末尾显示“本轮结束”。列表有序号、实际时间及输入轮次；重复的成功模型输出归到对应助手步骤，点助手详情的“查看模型请求”或时间线查看实际请求。“全部事件”展开完整记录，实际模型次数和用量不变。工具概述先展示状态、尝试次数、实际耗时及结果 / 参数摘要；模型概述先展示服务、模型和用量。较长内容在“预览”查看，关联 ID 和恢复预算在后面的关联记录 / 执行信息，完整脱敏字段在“原始内容”。搜索和状态筛选可以只看相关工具或失败步骤。窄屏详情为可关闭抽屉，Escape 返回选中行。

## 记录与展示

新任务记录用户输入、应用入口实际追加的上下文、每次实际主模型请求、助手公开回复、工具尝试、恢复决策和任务最终状态。模型重试、切备用与流式协议修正各自留下记录；工具回执复用、等待确认和取消前未执行的工具保留状态，但不计为新工具执行。物理请求与逻辑轮次分别关联，不把一次工具轮次当作一次 HTTP 请求。

步骤关联持久化会话、任务、Hermes 轮次、请求和工具调用 ID；有业务副作用时保留操作 ID。开始 / 结束时间使用 Unix 秒，耗时使用毫秒。用量来自供应商 / Hermes 标准 usage；缺失不补零，不据此宣称人民币账单硬上限。

旧对话使用已有用户、助手消息和工具回执回放，未记录的逐次模型请求、耗时与用量不推算。历史记录和新轨迹优先按 canonical 消息 ID / 工具调用 ID 去重；乐观消息只能在本会话按公开正文匹配，不吞掉同文的旧消息。

详情只读，不触发重新生成、工具执行或消息提交。正文和 JSON 均作为文本显示。SDK完整系统 / 开发者提示、模型内部思考、HTTP 鉴权头、密钥和媒体二进制不写入轨迹；敏感字段和签名 URL 统一脱敏。模型请求的输入展示权威公开对话投影；应用在提交入口追加的 `extra`（含澄清规则、项目等上下文）与澄清恢复说明，另以绿色上下文记录展示脱敏正文，不从SDK完整提示中提取。模型实际收到的输入保持原样。旧任务未记录的上下文不补造；提交前其他文本变换不宣称完整展开。内容有截断上限，必要的身份、结果状态、失败原因和用量优先保留。

## 本地读取

轨迹保存在本地 `miniclaw.sqlite3`，不启用外部遥测服务。读取接口沿用应用的同源会话 Token 鉴权：

```text
GET /api/miniclaw/traces?owner=<持久化会话ID>&limit=500&before=<sequence>
```

先核对 Hermes 权威会话及压缩血缘，再按序读取。返回 steps、has_more、next_before、revision；step.updated_at 用于防止迟到快照覆盖新的终态。加载最新窗口，用户可读取更早步骤。单记录 / 单页有上限，历史随使用累计，当前没有按天自动清理总历史。

轨迹页打开时加载，任务运行时每 1.5 秒读取，完成后补一次；隐藏、换会话和卸载取消旧读取，迟到响应不会串入新会话。读取失败保留已经展示的记录并提供重新加载。刷新可用 `?view=trace` 回到轨迹页；Composer 维持同一挂载实例，草稿和原对话阅读位置保留。

原 Hermes Agent 循环与权限边界继续负责执行。追踪写入失败不改变成功写入的业务结果，不因为记录失败而重放工具。服务启动时将未收到最终回执的运行中记录标为待核对，不伪造正常完成或跨停机时间的精确耗时。

当前追踪范围为 Chat 主循环及工具边界。JEV 预分类、自动标题、压缩等辅助服务的每次 HTTP 请求，以及媒体工具内部的供应商请求尚未逐次展开；媒体工具的操作回执仍可在对应工具步骤中查看。

## 恢复场景的 Trace 证据补查

2026-10-11，用户追问重试、超时、回退、兜底是否在 Trace 上验证。核对发现网络超时达到共享恢复上限、任务截止、主备额度均耗尽原先只有执行结果断言。本次新增三个针对性 Trace 测试，读取实际 SQLite 记录并检查数量、恢复事件、任务终态及友好错误。针对性 **3 项通过**，随后完整 `tests/test_chat_trace.py` **27 项通过（21.70 秒）**；产品代码与运行服务没有变化。

| 场景 | 已验证的 Trace 证据 |
| --- | --- |
| 主模型连续 503，备用成功 | 3 个主模型失败记录、2 次 retry、1 次 fallback、1 个备用成功记录；下一轮恢复默认主模型 |
| 主模型额度不足，备用成功 | 主模型仅尝试 1 次，记录 billing；fallback 后备用成功 |
| 网络超时达到共享重试上限 | 2 次实际请求 / 2 个失败记录、retry(timeout) → stop(retry_budget)，任务失败且保留停止原因 / 提示 |
| 整轮执行时间到期 | stop(task_timeout)、任务 failed、无遗留 running 记录；晚返回的传输结果不能将任务变成成功 |
| 主备额度都不足 | 两个服务各 1 次失败，fallback(billing) → stop(billing)，任务失败并给额度检查 / 已有结果保留提示 |
| 只读工具暂时超时 | 两个独立工具尝试 failed → completed，attempt 为 1 / 2，同一工具调用 ID |
| 写入结果未知 | 实际执行仅 1 次，unknown 与操作 ID；再次请求转 waiting / reconcile，不冒充第二次执行 |
| 回复传输中断 | 模型 failed / stream_interrupted，已收到的部分回复持久化，不自动重新生成 |

故障由隔离测试的本地 HTTP / 工具边界注入，经过实际 Hermes、SDK、恢复逻辑和 Trace 存储；没有耗尽真实账户额度或触发收费写入。真实浏览器当前验证的是正常调用链及轨迹交互，未逐项在页面人工演示上述故障。任务截止测试证明停止新增调用与正确收尾，不证明正在阻塞的网络线程被强制终止。取消、任务截止时保留部分输出及模型请求次数预算仍缺专门的 Trace 字段断言，不称为全部场景验证完成。
