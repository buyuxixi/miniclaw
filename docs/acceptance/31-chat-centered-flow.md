# 第三十一步：以 Chat 为中心重做商品创作交互

2026-10-04。用户否定第三十步的模块组织：把图片、口播和商品创作并列成工作台，仍然难以理解。此前的内部审查只能证明局部工程行为，未解决产品重心。本轮按用户明确要求重新组织主流程。

## 主次与交付

- Chat 是默认执行入口。侧栏顶部恢复新建对话和聊天记录；删除其上方三个模块切换入口，商品总览放在侧栏下方。
- 商品总览展示当前采用图片，以及创作方向、商品图片、口播主稿三个流程节点。一个主要按钮继续下一步；不在默认页展示模板、参数、上传入口和视频功能。项目设置保留手动资料和原有扩展功能。
- 节点进入同一商品的同一 Chat。顶部小任务栏切换方向、修图、口播；桌面旁边显示工作图或已采用主稿。用户只在主对话输入修改要求，结果栏不另设输入框。
- 修图发送携带对应工作画布的版本、主图片图层和商品上下文；没有手动附图时，在实际提交时准备当前商品图。口播沿用 spoken-script。进入节点不自动发消息、不自动生成。
- 手动精调是辅助入口，标题说明当前商品；直接返回同一对话，图层按钮不再打开另一套助手输入。刷新后仍恢复该商品的精调工具。
- 采用工作图先进入既有确认界面；暂不采用返回原修图对话。新图、新稿没有确认不会替换已采用成果。候选、版本和跨项目校验保留。
- 窄屏结果按需打开，关闭后继续输入。流程行可整行点击，任务按钮和结果入口至少44px高。

## 发现并修复的缺陷

1. 实际点击发现新结果栏使用了不存在的 export-to-chat 接口；已复用既有 send-chat 接口，并增加调用路径回归断言。只运行 mock 测试不能证明接口能用。
2. 定时刷新清除操作报错，用户点击后看似无响应。读取错误与操作错误分开，操作错误留到下一次操作；回归测试验证刷新后仍显示失败信息。
3. 精调收起工具及刷新恢复可能重新出现独立助手输入。关联项目固定为手动精调，助手入口直接返回 Chat，避免双输入。
4. 自动准备工作图可能把四个已有附件增为五个。现拒绝提交并保留草稿，要求先腾出位置。
