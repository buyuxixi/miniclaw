# 第六步：同一项目的 Chat 与封面回传

日期：2026-10-03。上一版用户评价：流程可运行，但三个模块分散，成片和 UI 未通过验收。本轮以实际作品为目标返工，不把测试通过写成用户验收通过。

## 实现流程

创作项目保存事实、主稿、视觉素材、成片、发布包和原生 Chat 的 `chat_id`。首次点击“带入 Chat 草稿”建立项目对话，后续恢复同一对话；继续使用现有 Hermes 控制器与 spoken-script Skill，没有另建 Agent 循环。

Chat 回复增加“采用为项目口播”。回传带目标项目与进入 Chat 时的 revision，在原项目预览、编辑、确认后保存。保留主稿即可，不把备选开头、说明或分镜表读入配音。已有未保存修改、项目不匹配、revision 变化均拒绝覆盖。

“在图片工作区打磨封面”直接把当前封面导入现有画布。画布增加“采用为项目封面”，导出 PNG 附件后在原项目预览；后端从当前 profile 的附件库按 owner 校验图片，复制成项目不可变素材，记录附件及画布项目来源。没有接收客户端任意文件路径。

入口：`CreatorWorkspace.tsx`、`AppShell.tsx`、`Message.tsx`、`CanvasApp.tsx`；后端 `creator.py`、`creator_routes.py`、`runtime.py`。

## 已执行验证与 review

- 浏览器真实建立项目对话，调用 deepseek-flash + spoken-script，回传六句主稿并确认保存，项目 v5→v6。
- 真实封面导入画布、导出、预览、确认，项目 v6→v7，封面来源记录为 canvas。
- 自动检查：草稿保护、显式确认、回传编辑、版本冻结；后端图片归属、CAS 冲突、原图不覆盖、临时文件清理。
- Review 发现并修复“进入任意当前对话”的断点；项目现在保留原生对话关联。已有待发 Chat 草稿被保留并提示处理。

## 串行验收步骤

1. 新建创作项目，填写事实和主稿并保存。进入口播步骤，点击“带入 Chat 草稿”，检查项目名与口播 Skill，然后发送。
2. 点击回复的“采用为项目口播”，只保留正文，确认后检查项目主稿。刷新后再次带入，应回到同一对话。
3. 添加封面，在视觉步骤打开画布，修改后点击“采用为项目封面”。检查预览、确认后的封面和来源标记。
4. 未保存稿件时检查回传入口不可用；在另一个页面修改目标项目后再采用旧结果，应提示冲突，不能覆盖新内容。

## 边界

Chat 草稿仍需明确发送；模型输出需要审核。回传框里的文字由用户选择，不宣称后端已认证每句话的模型来源。画布已有的云端修图能力保留；本轮样片回传测试采用完整画布导出，没有再调用一次云端修图来凑完成标记。新生成图片工具属于本次 Codex 制作素材，并未冒充系统已经接入文本生图 API。
