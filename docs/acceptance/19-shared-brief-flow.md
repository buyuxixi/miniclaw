# 第十九步：共享创作依据与固定 Flow 第一阶段

2026-10-03。用户授权进入实施。工程实现、相关检查与两个案例的真实网页验证完成，日常使用收益与创作质量待用户验收。

## 本阶段交付

- 推荐步骤调整为依据→图片→口播→视频→导出，仍可直接进入任意工作台。复用 Hermes、Creator、Canvas，不安装 Flow 引擎或主子 Agent 框架。
- 新增已确认卖点、目标受众、统一风格、必须保留与避免，商品事实沿用原字段；原图、采用图片、稿件保持同项目保存。
- Chat 每轮提交项目ID与节点，服务器核对关联对话并读取最新保存资料，资料经过引用标记中和后作为数据加入本轮。历史方案不替代本轮依据；素材ID不证明模型看见了图片。
- 每轮返回并保存项目版本、节点、依据签名。实时回复和历史重放继承所属轮次的来源，采用稿件使用该回复的原版本，不能用当前选择替换来源版本；其他项目回复不展示直接采用入口。
- 画布助手共享同项目依据。画布摘要增加位置、缩放、旋转和透明度，Agent可以读取人工编辑后的状态。人工操作与助手继续走已有服务和版本校验。
- 图片/稿件保存采用依据。修改依据或相关素材后提示核对，不自动重生成；支持核对后保留结果。整表保存时不把未改的稿件悄悄重新确认。
- 刷新恢复选中的项目Chat关联并核对对话归属。旧项目新增字段默认空，既有结果保留。没有来源元数据的旧Chat回复继续可读/复制，需要新轮打磨或手动编辑后采用，不能凭当前项目推定来源。

## 两个真实网页案例

### 概念精华液：新版依据与迟到回复

沿用「最低流程验收 · Chat口播与修图」，项目`0555c66ca1004ed888429379a5a0fc88`，Chat`20261003_204251_c5f904`。

1. 从v5保存卖点、受众、米白风格和限制至v6，沿步骤进入图片，核对并保留既有图片至v7，不请求生成。
2. 项目Chat发送不含字段值的复述请求，实际回复包含“关注商品包装设计的人”“米白背景、柔和光线、简洁克制”和包装保留/功效限制。
3. 手动改风格为“米白背景、低对比柔光、包装设计说明”，保存v8；同Chat再次复述，返回新风格。
4. 尝试采用v7旧回复，网页拒绝回传，v8与原有94字主稿不变。图片和稿件显示需复核，保留这个真实状态，没有为截图伪造确认。

原图、已采用图片与以前的一次百炼修图任务均沿用，不计作本轮新生成。

### 青瓷茶杯：画布内部动作与口播连续打磨

网页新建「共享依据验收 · 青瓷茶杯」，项目`fb56b1f3975c4cb2af96346c17637c1d`，最终v5。输入是既有`outputs/tea-film-v2/cover.png`概念图，不是真实商品实拍，不在外部重新生成。

1. 网页上传原图，保存青瓷/日常风格与无功效宣称限制。
2. 进入画布，关联项目自己的Chat。人工改图层名为“青瓷茶杯 · 手动调整”，旋转到3°，画布版本增至3。
3. 同Chat通过canvas-editor调用原生miniclaw_canvas_view，实际读出图层名、3°与“青瓷色、安静自然、日常口语”；不生成图片候选。
4. 人工恢复旋转0°至画布v4，采用导出的图片回原项目并确认至项目v4；原图保留。
5. 按下一步口播带入已采用图片和spoken-script草稿，同Chat真实生成主稿。首稿含未提供的触感/裂纹细节，拒绝采用；同Chat修订后采用51字主稿至v5，未由Codex在文件中代写。
6. 刷新恢复v5、依据、原图、图片与稿件；往返两项目检查风格独立。刷新Chat本身也恢复茶杯关联和历史来源。

本轮五次网页Chat提交（两项目分别2/3轮），一次包含画布只读工具。提交次数不等于供应商请求次数或账单。没有新AI图片任务、独立配音、视频、剪辑、发布或一键自动执行。

## 边界与后续

本阶段是固定业务Flow与同项目反复打磨，生成、比较、采用由用户交互推动。尚未实现通用执行器或自动续跑，未知任务/重启沿用已有明确失败与手动处理。

依赖签名按保存依据和相关素材ID判断，不做语义级分析。“已采用”不表示自动事实审核或商业质量合格；实际茶杯初稿说明共享状态不能消除模型编造，仍需检查与Chat修订。

后续先用用户自己的素材验证使用收益和质量，再决定语音/视频节点；暂不扩展通用引擎或多Agent。
