日期：2026-10-03。状态：只读调研、本地参考画面检查及自查完成；未安装 MCP、未新增系统功能、未生成下一版视频。成片效果仍未通过用户验收。

## 链接读取与 MCP 结论

当前可连接插件目录搜索“Douyin 抖音”未返回匹配插件。GitHub 有社区 MCP，但社区仓库存在不等于当前会话已接入，也不等于能获取此作品的播放画面。

| 项目 | 核对能力与状态 | 本轮判断 |
|---|---|---|
| [yc-w-cn/douyin-mcp-server](https://github.com/yc-w-cn/douyin-mcp-server) | MIT；解析分享页、获取播放链接、下载；没有画面分析模型。固定提交 f1e291f96d86ff29218efcf0b0239f97ba029e83 | 更轻，但依赖网页解析。源码找不到 play_addr 时仍拼接备用 URL，返回链接不能当作成功播放证据 |
| [yzfly/douyin-mcp-server](https://github.com/yzfly/douyin-mcp-server) | Apache-2.0；解析、下载及语音转文字；当前已归档。固定提交 b0bb8b1fbe4f514bf28099b1471928ebb3716ad2 | 归档项目不作为新核心依赖。源码区分 SiliconFlow 的 API_KEY 与百炼 DASHSCOPE_API_KEY；转写不是视觉分析 |
| [LIghtJUNction/douyin](https://github.com/LIghtJUNction/douyin) | AGPL-3.0；Rust CLI/stdio MCP，含官方 API/OAuth 能力。固定提交 c70a41e6a8007c09c9d955548f7ab63f25b26df1 | 官方 API 授权和任意分享链接画面读取是不同能力。本次不用发布接口 |

按第一个项目的移动端 User-Agent，对用户短链及 iesdouyin 分享页做只读 HTTP 探测：均返回 200，短链可跳转到作品 7635968742362467626；两份响应均不匹配该项目的 play_addr/url_list 提取表达式。没有下载远程媒体，也没有启动第三方服务器，因此结论是“该解析方式没有提取到播放地址”，不是“所有 MCP 都不能用”。固定源码、仓库元数据和脱敏探测记录位于私有目录 `.codex/references/douyin-mcp/`。

此前网页和浏览器读取失败的环节是播放器画面，而不是不知道作品链接。用户现在提供本地 MP4，画面分析可以直接进行，不依赖抖音登录或安装 MCP。今后真有重复导入链接的需求，再把链接解析放在素材导入入口，失败时允许文件上传；不增加一个导演 Agent。

## 本地素材与验证证据

本轮成功解码并检查 14 个采样时间点的全分辨率画面，证据在 `outputs/buv-reference/`，元数据与原文件 SHA-256 在 `metadata.json`。时间点是观察采样点，不是自动检测出的精确剪辑点。没有完整听评、语音转写或音画节拍测量；无法仅由该文件确认它就是链接原作的完整版本。

## 对上一轮方案的修正

第十三步建议产品镜头占 70–80%，当时没有观看参考。现在实际观察到参考包含大量人物镜头，因此不再把这个固定比例作为验收条件。问题是每个镜头是否服务同一件商品：背景色、材质、展示动作、信息层和结尾是否形成一致表达。

我们的实拍茶具 v3 主要改善了素材真实性和配音计时；素材以生活方式为主，缺少同一商品的精细包装/外形展示、受控灯光、材质微距与真正依附商品的效果。调整色彩、加字幕或安装 UI 库无法补齐原素材缺失的产品摄影。

下一次制作先用同一件产品验证三个镜头：产品定格、材质微距、一个依附材质或动作的特效。镜头通过后再串联口播、音乐及收尾。商品素材、修图输出、主稿、配音和视频仍挂在既有同一创作项目；优先提高镜头质量，不扩展多 Agent 或选品发布链路。

## 验收步骤与本轮自查

1. 用本地播放器打开原文件，确认时长与上述产品画面；打开 `outputs/buv-reference/at-7.5.jpg`、`at-10.2.jpg`、`at-11.2.jpg` 比对描述。采样图可检查视觉，不能替代完整音画评审。
2. 查阅固定提交的源码和探测 JSON，确认社区项目能力、归档状态及网页返回 200 但播放地址未提取；本轮没有声称安装或完整 MCP 联调成功。
3. 下一版逐镜核对同一商品外形/文字一致性、材质细节、阴影与高光、特效与商品的关系；核对每句旁白对应画面，无无依据的功效宣传。不能仅以分辨率或接口成功判定效果合格。
4. 完整成片再检查播放、字幕、响度、首尾节奏、同版本发布包，并提交用户评审。

自查结果：已把“标题/URL 可读”和“视频画面可读”分开；把源码能力和运行验证分开；修正了没有观察支撑的固定主体时长建议；没有把语音转写 MCP 描述成视频理解。此次仅研究与文档，不运行软件回归测试，也不把下一版作品标记完成。
