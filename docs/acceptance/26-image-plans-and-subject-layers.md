# 第二十六步：Chat修图方案与主体背景拆层

2026-10-04。用户授权把提供项目和Skill中有用的能力全面参考适配，特别把修图作为工作系统的核心环节。本轮落实共享动作注册、有限多步方案和已有选区拆层；自动识别/OCR、扩图、专门超分、批量营销仍未完成。

## 实际实现

- Chat与UI复用14种方案动作：调色、翻转、移动、缩放、旋转、透明度、显隐、文字、层级、画布裁剪、画布尺寸、底色、主体背景拆层、AI候选。参数在后端校验，动作绑定本轮项目、版本和目标层，不接受模型提供的任意路径。
- 最多六步、固定先后。本地步骤组合成一个真实预览，确认后整体写入一个可撤销版本，画布文档与方案状态同事务提交。最多一个AI步骤且必须最后；选区AI独立提案。没有通用Flow调度、拓扑执行或任意步骤自动重试。
- 提案持久化到同一SQLite；刷新可以重新读取。预览创建不可变候选素材，但不改当前文档；确认应用后才改文档。工作图、Chat归属或主体选区变化，旧方案拒绝执行。
- 新的“修改目标”入口用同一个Chat先提案，用户看预览并应用；高级参数和旧方案折叠，结果可继续调整。已提交云端任务沿用固定请求ID，重复点击不重复提交；取消停止接收，服务重启不重放。
- split_subject需要已有确认的主体选区，将原照片拆成保留主体与可编辑背景。背景沿用目标层ID，主体在上方；可随后单独对背景生成候选。采用二值边界分配原像素，原合成可保持；这不是自动语义识别、OCR拆层、智能补洞或完成的商用抠图服务。需人工检查细绳/半透明和边缘。
- 方案AI只读取冻结版本的当前可见范围，裁剪画布外的截图界面不发给模型；合成结果保留画布外原像素。已有手动图层AI默认行为保持兼容。
- 框架保持一个主Agent。方案轮次在原生pre_tool_call钩子中仅允许画布读取/提案/查询和设计资料读取，直接编辑、终端或无关文件工具被拒绝；非方案轮次沿用现有权限。不会因勾选Skill自动开放工具。

## 原生试跑

使用现有深绿茶壶试跑画布`94014b0eb93f4a6aa37f87b2cb58b60d`，并保留两个正式商品和乳白失真候选审核记录。

1. 输入“右侧增加160像素留白、底色暖白、照片像素/位置/大小不变，只给方案”。首轮发现安装正文升级但工具依赖还是旧版，发送被拦截。补充仅识别既有内置正文与依赖的迁移、备份及自定义保护；未更改用户工具权限。
2. 第一份方案成功，但回复不知道resize_canvas是否移动图层，且尝试终端/无关资料查询。方案取消。补操作语义与方案轮次的原生工具钩子；前端只发送用户目标，内部规则由后端注入。
3. 最终第二轮实际Chat只调用读取工作图和提案工具，生成方案`7f566d7ed0134c67953e244db71eeb8c`。目标与保留项为普通中文；提案时文档保持1280×950/revision5，未执行。
4. 原生预览展示修改前后，再明确应用，变成1440×950、暖白底/revision6/cursor3。导出前1280×950区域逐像素等于原始照片的既有裁剪；右侧像素为(242,239,231,255)，照片图层文档完全不变。
5. 320×672刷新、重新打开助手：画布、历史与方案状态和应用后完全一致。原图与两正式封面hash、三个Creator项目、白壶画布与拒绝审核记录均不变。
6. 最后原生撤销试验构图，恢复1280×950/revision7/cursor2；document等于试跑前。方案保留为历史应用记录，不代表此刻仍采用该构图。临时viewport恢复默认。

最后可见范围修正后重启服务，只读复核再次通过：revision7、原工作文档、两条方案状态与三个Creator/正式封面/白壶审核记录保持，无自动重放。
