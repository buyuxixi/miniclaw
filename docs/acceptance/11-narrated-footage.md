# 第十一步：镜头片口播与指令配音

日期：2026-10-03。状态：实现、自动验证、真实Serena配音和本机成片完成；审美及声音偏好待用户验收。系统新增一个固定合成模式，继续复用现有创作项目、Chat、画布、队列与发布包。

## 实现流程

入口：创作工作台 → 视频 → 制作方式「镜头片口播 · 配音＋字幕」。上传已经剪好的视频，保存本项目主稿，选择声音，再显式点击合成。用户可继续从项目关联Chat采用主稿、从原有画布采用封面；没有新增第二个聊天控制器。

- `storyboard.py`保留默认Cherry/qwen3-tts-flash，新增固定Serena自然温柔、Ethan沉稳旁白。后两项使用百炼 `qwen3-tts-instruct-flash`、`instructions`和`optimize_instructions`，依据[官方Qwen-TTS接口](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。只读取项目已有的北京地域 `DASHSCOPE_API_KEY`，不自动换Key/重试。
- 真实Instruct首次返回的OSS桶与旧Flash不同。针对实际验证的北京结果host增加精确许可，保留HTTPS升级、凭证/端口检查、禁止重定向；未泛化允许任意阿里云桶。失败记录保留，没有向前端或文档暴露Key、签名下载URL。
- `narrated.py`逐句读取受限实际PCM，规范化WAV、转48kHz单声道，字幕边界取实际音频时长。开头0.35秒、最小句间0.28秒、至少片尾1.2秒；多句按镜头片剩余时长分配句间留白，上限2.5秒，避免全说完后留下长空尾。单句/过长镜头仍可能有较长尾部，需缩短镜头片；这不是逐字ASR，也不是自动按画面语义对齐。
- 保留上传镜头片完整画面和时长，输出1080p/H264/AAC。默认替换原音轨；显式勾选「保留背景音，旁白时自动压低」才混合原首音轨，保留其时间偏移，并做旁白侧链压低及限幅。已有视频内音乐需要使用者有权使用。没有原音轨时禁止勾选/合成保留模式。
- 主稿最多320字、12句、每句36字。镜头片不足时明确失败，不循环素材、不截掉旁白，且停止请求剩余句子。已经请求的语音仍可能计费；失败任务的部分音频目前不会参与复用。
- `creator.py`签名包含主稿、镜头片、比例、声音指令、背景音开关与配方版本，修改实际依赖使旧视频/包过期。复用只取同一项目、同模型/声音/完整指令/正文的已完成音频。画面或节奏重做可以复用旁白，换声音必须新合成。
- UI字段、服务端白名单、任务冻结、revision/CAS和认证下载继续沿用原项目。发布包自动取该产物的生成SRT，不误用旧上传字幕。

## 验证与人工验收

本轮47项前端、23基础API、8图片、12画布、6编排、7创作、4图片口播、4镜头片口播、1技能包检查，共112项通过；TypeScript/Vite构建通过。地址兼容和间隔调整后，受影响的镜头片4、图片口播4、创作7项再次通过。

四项新检查覆盖官方指令请求、精确下载host与伪域名拒绝、声音/正文签名、真实FFmpeg完整时长/原声替换/实际字幕、背景混合及0.6秒原音轨偏移、无音轨拒绝、短片阻止继续请求。默认图片模式音频复用与旧视频模式继续验证。

1. 上传自己的镜头片和短句稿，选择Serena并保存。点击合成前检查明确的计费说明；预期原始视频不被覆盖。
2. 播放，检查画面剪辑保持、中文字幕只在对应句音频区间显示、最后一句不被截断。音色自然度需听感验收，测试不能替代。
3. 默认替换原声；再按需要保留自己有权使用的背景音，核对旁白清楚且原音轨偏移保持。
4. 修改稿件/声音/镜头片/背景音开关，旧视频应过期；只修改文案不必重编码，但需重建包。
5. 镜头片太短应报错并保留失败记录；不要为了看效果反复点合成。检查发布ZIP中video/cover/SRT/稿件同版，平台仍由用户手动发布。

新样片镜头挑选、预剪与海报式片尾由Codex本次制作，应用从上传的预剪片开始处理。系统尚未自动找素材、自动导演、自动完成多源剪辑或自动生成视频；不能将本次作品制作能力误写为这些接口都已接入。Ethan参数经离线协议检查，真实新样片只验证Serena，尚未试听Ethan云端效果。
