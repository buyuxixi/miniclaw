# 第二十二步：创作续作、依据采用与口播打磨

2026-10-04。用户授权“继续优化”，承接[第二十步真实素材流程](20-real-product-material-flow.md)和[第二十一步评价体系](21-user-experience-and-content-quality.md)。本轮修改现有工作台并原生复验，保留一个主 Agent、共享商品资料和可视化节点工作台。

## 实际改进与操作入口

| 问题 | 当前行为 | 用户入口 |
|---|---|---|
| 新导入画布刷新恢复旧图 | 导入完成记录当前画布；刷新恢复同一文档和历史 | 图片工作区刷新 |
| 主 Chat 返回修图重新导入 | 继续当前商品工作画布；按对话、当前输入图片核对缓存，服务器校验归属及归档状态 | 主 Chat 顶部“修图”、项目“图片工作区” |
| Chat 建议需要人工复制五项资料 | 回复显示自然语言字段，可预览、编辑、确认采用到共享依据 | “让 Chat 整理卖点与风格”→回复“采用为创作依据” |
| 采用口播带入说明、备选和分镜 | 优先提取主稿，仍保留可编辑确认；不自动保存 | “带入 Chat 草稿”→回复“采用为项目口播” |
| 已消费建议在切换商品后重复注入 | 建议绑定对话，成功进入草稿即消费；重新挂载输入框不重放 | 发送后切换商品，再返回 |
| 图片预览误标9:16，能力描述不明确 | 静态图片显示实际原比例；附件按当前路由提示是否发给模型 | 项目视觉预览、Chat 附件提示 |

候选仅允许 facts、selling_points、audience、style、constraints 五个字符串字段，检查数量、长度、格式和NUL；兼容实际模型使用的 creator-brief/json 围栏。额外、缺失、损坏或重复候选不提供采用按钮。候选绑定发起轮次的项目、对话和版本，迟到、串项目、旧版本及未保存修改不能覆盖当前资料。采用前需要人工核对；格式校验不证明商品事实真实。

面向用户的提示词使用自然语言，候选格式约定放在后端受信任上下文。买点与受众偏好写成建议，材质、工艺、容量、性能、价格无证据时保留未知。口播 Skill 补充“特征→卖点→购买理由→依据”、针对性开头和自然结尾，去掉人物衣物等无关内容。更新的是本项目已有 spoken-script Skill；本机副本与旧版本一致后才同步，原备份保留。工作台检测依赖变化后，在设置中重新核对并保存原有零工具依赖，未扩大工具权限。

### 看图能力判断的纠正

操作中曾仅凭模型名/声明不足，过早认定当前模型不能读图，并要求只用文字；该判断已向用户纠正。实际应用配置路由为native，最新网页显示“当前配置会把图片发给模型；识别结果仍需核对”。这证明当前输入方式，不证明识别总是正确，更不证明商品材质与性能。

只读收集器拿持久化Chat ID查询需要实时session_id的能力接口返回404，记录为查询ID不适用，不解读为缺少视觉能力。以后必须区分路由、输入、识别结果及事实证据。

## 复评与剩余用户难点

沿用第二十一步“准备短视频商品推广素材”的目标及权重，不改变门槛来提高得分。

| 维度 | 乳白 | 深绿 | 判断依据 |
|---|---:|---:|---|
| 图片 | 15/20，保持 | 14/20，保持 | 文件未改；主体完整，仍缺竖屏封面版式，高光等短板保留 |
| 口播 | 12/20，原8 | 12/20，原7 | 新增偏好人群切入、聚焦外观和自然比较引导；仍未实际试读、没有功能证据或受众反馈 |
| 续作与恢复 | 本次通过 | 本次通过 | 原生专项裁剪、刷新、返回，及跨商品往返 |

以上为开发者主观复评，不是用户评分或转化率。没有商品性能、用户需求及发布数据，不给完整100分总分。稿件可用作外观介绍候选，不能据此判整条商品推广内容可直接发布。图片可继续作为展示/视频输入素材，未升级为商用竖屏封面。

用户仍需核对模型事实及建议、选择编辑范围、确认图片与主稿。裁剪这轮仍是人工操作，没有验证一句自然语言完成全部裁剪、修图和采用。尚未让非开发者独立走流程，也没有对照计时。下一项有实际必要性的验证是让3位非开发者各完成一次导入、修改、采用和恢复，记录求助与误入；随后用反馈决定是否补意图到图片动作、质量检查卡。暂不扩展通用Flow、多Agent、配音、视频及发布。
