# Chat 导航、历史与多图镜头返工验收

2026-10-07，Asia/Shanghai。针对用户四张实用截图反馈的纠正。此前 28 号记录只证明了局部修图链路，遗漏日常导航、旧历史和多图镜头，不能据此宣布普通用户整体可用；本记录补充并修订该结论。

## 改动与边界

保留原深色、浅紫自由空间画布、完整自由 Chat 和完整精修编辑器。采用、历史、图层与原有项目内容保留。

- 画布的三个完整 Chat 入口改为当前标签页跳转，并先完成项目保存；保存失败留在画布展示原因。
- 会话关联只表示资料关系，不自动激活旧 Creator 工作台。旧工作台需要显式从旧创作项目进入；自由画布的 Chat 路由始终保持完整普通聊天。切换历史退出旧任务模式，刷新旧任务只恢复明确进入过的同一 owner。
- 历史选择和新建对话将会话 ID 保留在 URL；刷新继续当前选择，不把全局历史或新对话重新绑定成项目对话。
- Chat 的画布返回入口使用一致的按钮样式，侧栏直达自由画布，移除该路径上的旧“开始创作/创作看板”入口和误导的新窗口箭头。无关历史不显示“放到当前项目画布”。
- 多图片段返回正常选图状态，展示原始海报、细节参考的缩略图和“已选中”反馈。每个片段的每张参考图有独立工作文档；服务端校验该图确实属于片段，采用只影响选择的输入。无图镜头和方案节点允许正常讨论。
- 有草稿时锁定图片选择；显式“清空草稿”保留当前选图并解除锁定。重新读取可放弃失效的选图引用，文字草稿保留。
- 多图采用产生派生素材 ID 后，将新引用继续关联原精修文档，并同步导演选图；保留图层与历史，避免续改重新创建扁平工作图。
- 服务端读回后清理不属于当前项目的旧活动对象和导演引用，避免跨项目浏览器缓存带来错误目标。
