# 资料附件上传、解析与分析

> 当前实现：2026-10-11。用户希望先建立通用能力；已用46.9 KiB Word验证真实关键词问答、8.857 MiB / 131页PDF验证解析与检索。全文模型综合和批量文件的业务效果仍待用户验收。

## 上传与恢复

普通 Chat 一轮最多 **10 个附件**，已上传和待上传文件合计计数。PDF、DOCX、CSV、XLSX、TXT、Markdown（`.md` / `.markdown`）及 SRT 单文件最大 **50 MiB**；PNG、JPEG、WebP 图片继续限制为 **5 MiB**。不支持旧版 `.doc`、`.xls`。文本文件须为可读取的 UTF-8 内容，最终格式和有效性由服务端校验。

在输入框点加号多选，或把文件拖到输入框。粘贴图片沿用原入口。上传队列同时处理最多 **2 个文件**，每项显示等待、进度或失败原因；一个文件失败不会停止后续文件，成功项保留，失败项可以单独重试或移除。待上传数量在入队时预占，连续添加也不能突破 10 个限制。

传输使用最多 **4 MiB 的原始字节分片**，每片校验 SHA256。浏览器只保存上传 ID、文件身份与分片清单，不保存大文件的 base64 内容。刷新或关闭后重新选择原文件，客户端会核对已上传分片的内容并继续缺失部分；同名、同大小的不同内容不会拼接成旧文件。临时上传有并发/容量限制和过期清理，过期后需要重新上传。

取消停止当前上传并清理对应临时会话。上传期间切换对话，晚到结果保存在原会话草稿，不加入新会话。第一次上传会保存原生会话，即使尚未发送消息，重启后也能恢复同一附件归属。移除成功附件只取消本轮引用，历史消息和原始文件继续保留；正式附件与历史对象尚无完整自动 GC 和总容量管理。

画布导演助手仍用于对比图和圈选反馈，保持最多 4 张、每张 5 MiB，复用新的传输客户端。自由画布、图层精修和旧 Creator 的独立素材入口继续遵守各自限制，不能据此声称所有图片/视频入口均已扩大。

## 上传分片与分析分块是两层

上传分片解决网络传输、中断恢复和字节完整性。解析完成后产生的文本块、表格行及来源索引解决阅读与分析；上传成功不代表已经读完文件，也不代表已经完成用户要求。

原文件在本机保存，解析也在本机执行，解析本身不调用模型。解析后，模型通过经过归属校验的附件 ID、分块和查询工具读取资料，不把 50 MiB 原文件一次塞入聊天上下文。Chat 调用资料工具或启动模型分析时，所选的相关内容会进入已配置的模型服务。

上传完成就进入本地基础解析队列，最多2个解析worker，不等待用户提问。提取文字、表格、来源并保存索引之后，提问才决定后续怎么使用资料。小原文件并不保证展开内容少：DOCX是压缩包，当前所有PDF/DOCX/CSV/XLSX都用引用与查询工具；只有不超过64 KiB的TXT/Markdown/SRT、且本轮小文本合计不超过128 KiB时，保留旧的全文内联方式。

| 格式 | 当前解析范围 | 应核对的限制 |
| --- | --- | --- |
| PDF | 文字型 PDF 的可提取文字，保留页码；合法Unicode代理对合并为字符 | 没有 OCR；扫描页、图片中的文字、复杂版式不能假定已经读取；损坏字体编码以�占位并按页警告，继续后页且保持partial |
| DOCX | 正文段落、标题与表格，保留段落/表格/行来源 | 不含页眉页脚、批注、脚注、文本框；内嵌图片及复杂表格报告覆盖警告；不支持旧 DOC |
| CSV / XLSX | 表头、工作表和数据行，保留表名与行来源 | XLSX 不重新计算公式；缺少公式缓存、错误单元格和列结构问题会报告；不支持旧 XLS |
| TXT / Markdown / SRT | UTF-8 文本，保留原文件行号 | 不执行正文指令；文本读取不等于理解全部上下文或校验字幕时间轴 |

附件卡区分“等待解析 / 正在解析 / 可使用 / 部分可读取 / 解析失败”。带新解析状态的小文本同样刷新状态；旧文本附件继续兼容。失败、停止或部分可读取的解析均可手动重试，原文件下载仍可用；大文档只在点击下载时读取原文件，不为显示卡片提前加载整个文件。部分可读取不会自动反复重试。

输入区使用紧凑预览卡：图片显示缩略图，文档显示格式图标，文件名在底部，右上角移除本轮引用。部分可读取和处理中的状态继续显示；点击文档卡查看完整文件名、大小、文本块数、实际读取范围及警告，并下载或重试。多个附件自动换行，超过可见高度后在附件区滚动。关闭详情保留草稿；重试后移除引用，迟到回执不会把附件加回输入区。

发送后的用户消息复用同样的预览卡，与正文右侧对齐；没有草稿移除按钮，仍可打开详情和下载。既有历史消息刷新后也使用新展示，无需重新发送。图片预览、编辑及在已关联项目中加入画布的原操作继续保留。

`partial` 表示有真实覆盖缺口，可能是无法读取的页/对象、公式或解析上限。应查看警告及页、工作表、行、段落定位；`units_seen` / `units_done` 是实际进度，未知总量不补成“100%”。分析结果必须说明来源范围，不能把部分可读取或预算暂停写成完整结果。重新解析使用新的解析尝试；分析任务固定创建时的对象、解析版本与来源清单，来源改变时必须停止或报错，不能悄悄读取新版本。原文件和历史附件引用继续保留。

PDF的字体映射可能产出无法保存为UTF-8的代理半字符。`local-v2`将合法代理对无损合并，对孤立字符使用�并记录实际数量、页码及数学符号核对提示，后续页面继续解析；不猜测丢失字符。这样的PDF可能已处理所有页、仍有部分页的内容缺口：例如131页均已处理、120页无此编码缺口，状态仍为partial。已有索引不因部署自动重解析，手动重试会使用新版本。

## 先判断要完成哪种任务

| 意图 | 处理方式 | 用户可以这样说 |
| --- | --- | --- |
| 定位 `search` | 本机合并字面关键词检索，返回去重命中、有限相邻上下文及来源 | “在手册里找‘保质期’，告诉我页码和原文。” |
| 扫描 `scan` | 有表格时逐完整数据行处理，无表格时逐文本块处理，后台保存每项结果 | “逐条检查销售明细，列出字段缺失或矛盾的记录。” |
| 综合 `summarize` | 分块处理后分层汇总，保留差异、矛盾与来源 | “综合这几份资料，区分共同结论和互相冲突的说法。” |
| 计算 `calculate` | 本机结构化过滤、分组与 count / sum / avg，保留列名和来源 | “按渠道汇总销售金额，再计算各渠道平均订单金额。” |

当前 `search` 是 **字面关键词检索，没有向量检索**，也不保证同义词命中。检索命中若干段不等于全文扫描。数字统计使用验证过的列、筛选和 Decimal 计算，不让模型凭抽样估算总数；缺失值、非数字值、未知列和覆盖缺口必须明确处理。

搜索支持`query`单关键词，或`queries`数组（1–5个相关关键词，OR匹配）；两者恰好提供一个。`context=0..2`可带命中前后相邻块，默认0。例如`action=search, queries=["附件","解析"], context=2`一次返回两个词的合并结果，按文档顺序去重。`limit`和`offset/next_offset`只分页真正命中，邻块另外标记为`context_ordinals`，不消耗命中分页；下一页仍可能把上一页邻块作为真正命中返回。共享预算优先保命中，未装下的邻块以`context_truncated=true`说明；完整工具搜索响应不超过48,000 UTF-8字节。

定位问题提示模型先合并相关关键词，有足够证据后回答，只在上下文不足时补读。该提示和批量工具减少重复查询的机会，不保证模型固定只调用一次。Chat与Trace显示搜索词、读取位置和具体动作，详情保留原工具名称及参数。

测试两条路径可以分别提问：“帮我找一下比重差的知识，给出页码”验证分块后的检索；“请对整份PDF分块总结，再汇总为知识点目录，标明页码和解析缺口”验证全文分块综合。后者应创建`miniclaw_document_analyze`的summarize作业；块可以按输入预算合并为一次模型请求，文本块数不等于调用数。上传后的本地分块不代表已经完成这项模型任务。

目前含表格DOCX的`scan`只处理表格数据行，不同时逐段检查正文；`summarize`使用全部解析文字块。需要“正文与表格每一项都检查”的混合扫描尚需补充，不能用表格行扫描的完成状态宣称整份混合文档已逐段检查。

相关工具为 `miniclaw_document_query` 与 `miniclaw_document_analyze`，归入资料附件工具组。对话需要实际加载工具；只看到设置项不表示旧会话已经加载。查询工具提供资料元数据、分页读取、关键词检索、计算及后台分析状态。全文任务通过 Chat 指令发起，不新增分析工作区；工具返回排队/运行状态和任务 ID 时，先保留该 ID，之后查询进度与结果。

## 全文任务、预算与未知回执

`scan` 和 `summarize` 使用持久化后台任务，固定当次附件对象、解析版本、要求和预算，保存检查点及已完成结果。达到边界或重启不会自动重新分析已经完成的单元。

默认预算为 **128 次模型调用、16 MiB 累计模型请求输入字节**，与上传文件大小和 Chat 本身的预算不同。输入预算包括实际分块与汇总请求的内容；调用及字节在请求发出前保守预留。它们不是人民币账单硬上限，实际费用取决于配置的模型及供应商。

达到调用或输入预算会暂停并保留完成部分。扩大预算、恢复任务或重试未知步骤需要用户在当前任务明确确认，因为可能新增模型费用。网络中断或服务重启后，已经发出但未拿到确定回执的步骤标为 `unknown`，**不自动重试**；应先核对，再明确决定是否重试。取消停止后续请求并保留已完成结果，正在进行的单次请求仍可能产生费用。

“已创建任务”“已解析”“正在综合”“部分完成”分别表示不同阶段。只有来源覆盖、逐项处理及汇总都满足当次要求，才能称为完成；文件解析的 `partial`、缺失单元、失败步骤和预算暂停均应出现在结果说明中。

## 验证与边界

本轮前端 `npm test` 为 49 个文件 / 392 个测试通过，`npm run build` 的 TypeScript 与 Vite 检查通过，覆盖分片传输、续传校验、同名替换、队列容量与并发、部分失败重试、取消晚回执、草稿恢复及文档状态。后端附件四模块最终 71 项、相关聊天四模块 80 项通过，使用真实解析器、SQLite、FastAPI、原生插件和会话恢复路径，模型边界使用离线替身。

50 MiB 原文件通过中断续传和 SHA256 检查；49.16 MiB / 5 万行 CSV 通过解析与全量 Decimal 分组统计。实际本地界面完成 10 文件上传、部分读取说明和刷新恢复，390 像素窄屏无横向溢出。验证目录：`.codex/verification/attachment-processing-2026-10-11/`。

用户真实Word问答显示两次单词搜索后补读章节，三次都成功且无重试。后续优化以该轮已有解析结果做只读回放，验证合并检索的命中与来源；没有为此次优化发起在线模型请求。大文件/多个文件已做工程验证，但用户尚未亲自验收；离线替身、接口检查、只读回放和页面快照不能证明在线模型选择最少调用、摘要准确或扫描无漏判。
