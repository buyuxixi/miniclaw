### 布局与视觉

- `frontend/public/studio/tokens.css` 使用面板 `#fbfaf7`、画布 `#e7e4dd`、文字 `#2b2925`、强调色 `#c4572e`。默认连线单独使用 `--ui-connection: #80786d`，与画布约 3.5:1；选中线变橙色，路径几何保持不变。图片缩放手柄、备注来源、选中框等旧紫色残留改用共享变量。
- 左素材栏保留展开 248px、收起 44px；右侧新增 352px 固定“属性 / 助手”工作面板。图片要求、镜头提示词、模型选择和生成动作放进属性区，编辑设置不再作为浮层压住图片和连线。画布让出两侧实际宽度；“定位节点”是显式动作，普通选中与展开设置不会擅自移动视野。
- 项目资料按桌面双栏排版：共同要求和镜头列表是主区，生成次数与最近记录放侧区。保存上限紧贴输入，错误和失败计数说明保留；正文 14px、辅助信息 12–13px，长名称可以换行。回到画布和关键保存动作使用橙色。
- 镜头采用状态使用稳定的不透明底色，避免产品图片的颜色影响文字对比。属性、助手、模型菜单与项目资料沿用短过渡，并尊重减少动态效果设置。
- 内嵌完整精修的工具、选框和选区接入共享暖纸/柿橙颜色；“适应”视图为底部缩放条留出空间，工作图边缘完整可见。仅宿主视图使用该适配，媒体像素及正式版本不受配色影响。

主要入口：`index.html`、`style.css`、`tokens.css`、`node-composer.js`。这轮没有把 Alpine 自由画布改成另一套前端框架。

### Chat 图片加入项目与真实来源

- 已关联项目的 Chat 图片附件和成功修图结果新增“加入画布”。保存成功后显示“已加入画布”或“画布已有这张图片”，并提供定位到节点的链接；原对话、图片和输入草稿保留。
- `POST /api/workspaces/{workspace}/assets/from-chat` 接收当前运行会话、附件 ID 与请求 ID。服务端确认运行会话对应的持久 owner、项目 Chat 关联、附件归属及图片 MIME，再引用已有 `file_objects`，通过正式版本记录授予项目媒体权限，不复制文件。
- 加入操作在 SQLite 写事务中读取最新项目，仅追加素材节点，不替换整份客户端草稿；记录实际 revision 与回执。同请求失败重试、同字节的另一个附件、并发加入，以及原节点采用新图片后的再次加入，都不会多建同一素材节点。复用用户已有节点时不覆盖它的来源。
- 新节点保存确有的会话、附件、文件对象，以及已有的图片任务和父级来源。属性区“查看来源对话”先完成本地保存再打开项目原会话；只有真实 `messageId` 才生成消息定位锚点。没有消息 ID 的附件或任务来源回到项目对话，不伪造“第几轮生成”。

主要入口：`studio_projects.py:add_chat_image`、`studio.py`、`ChatImageCanvasAction.tsx`、`AttachmentCard.tsx`、`ImageJobCard.tsx`、`Message.tsx`、`App.tsx`。本轮打通已有附件与结果卡片；Markdown 正文中的任意图片 URL 仍由原有展示规则处理，不能把这条素材入口写成所有远程图片均可导入。

### 两侧真实变更反馈与草稿保护

- 嵌入助手在真实工具完成、整轮结束或活跃执行失败时发送同源 `miniclaw.director.changed`；历史恢复、事件重放和其他会话不会因渲染而宣布变更。外层重新读取项目并比较 revision，未改变的项目不会被当作新增操作。
- Chat 的“画布记录”读取 `GET /api/workspaces/{workspace}`，显示最近三条真实 `events` 的原始标签、时间和项目版本。对象仍存在时才提供定位链接；空记录、读取失败和重试有明确状态。它是项目保存记录，不向 Hermes 插入模型消息，也不复制历史成为第二套 Chat。
- Chat 加入素材后通过 `BroadcastChannel('miniclaw-studio')` 通知关联画布与记录区；浏览器恢复焦点、真实执行结束及重新连接也会读取最新状态。连续通知只合并后续读取；切换项目、运行会话或卸载后，旧请求不能把结果写到新项目。快速断线重连会立即失效旧读取，即使 React 尚未渲染连接状态也不会注入迟到结果。
- 画布刷新完成网络读取后再次检查本地状态。存在未保存编辑、拖动、待确认回执、项目弹窗或精修工作区时，不直接覆盖当前内容。冲突会保留草稿、暂停自动保存并显示“备份并读取更新”；读取或备份失败时保留当前页面和错误，供用户重试。

主要入口：`StudioDirector.tsx`、`StudioChanges.tsx` / `StudioChanges.css`、`workflow.js`、`integration.js`。真实保存记录只表达服务器已有事实，不把普通文本回复一律描述为“修改了画布”。

### 剪辑与精修返回

- 剪辑轨道选择已采用片段时，使用真实视频任务的 `shot` 关联原镜头；“定位画布镜头”返回画布并定位该节点。镜头属性中的“在剪辑中查看”选中其已采用片段。原镜头已移除或片段暂不可读时提示实际原因，已生成视频保留，不按名称猜测来源。
- 完整精修继续使用同项目 iframe 和正式版本接口，左侧展示当前原图及关联镜头数量，右侧为图层、选区和编辑器。打开前保存项目，比较后明确采用才更新原节点与关联图片输入；已有视频保留生成时的来源，需要新视频时由用户重新生成。
- 返回画布恢复打开精修时的节点选择；该节点已移除时才回退到仍存在的原素材。助手重新读取编辑上下文。若采用结果返回前画布又有新编辑，保留本地草稿并提示处理版本冲突，不覆盖迟到期间的编辑。

主要入口：`production.js`、`workflow.js`、`integration.js`、`index.html`。精修使用既有版本链与比较能力，本轮没有以自动新增一排版本节点替代正式历史。

## 第 2 步（第二部分）：柔化配色，去掉黑白配（进行中）

### 为什么

用户反馈：风格方向可以，但 AI 味重、黑白对比太硬，要整体统一、柔和。第一部分没有按 `docs/DESIGN.md` 的约定加载 oil-ui-pro，这次补上，按它的"模型默认审美自查"诊断：墨黑实心按钮和品牌块、纯黑字配暖白底、标题一律加粗 600–650、强调色（深蓝）和产品图的绿色没有关系。

### 怎么改的

1. `tokens.css` 换成"陶土"配色：底色、面板、凸起三层只差色温不靠黑白；文字从 #1d1d1b 改为石墨橄榄 #34332e（对比度 11.6，仍满足阅读）；强调色从深蓝改为取自产品图的灰绿 #4d6b63，新增 `--ui-accent-hover`、`--ui-accent-soft`（浅绿底）、`--ui-pressed`。
2. 实心深色元素改为强调色或浅绿底：品牌块、"新建对话"、画布"+"、发送按钮、"打开画布"、回复标记。
3. 原来写死的蓝色（#2346ba、#3e628c、#2749aa）和黑色（#1c1c1c、#2d3239）在 Chat、项目页、设置弹窗里换成变量。
4. 大标题改为常规字重、加大字号（项目页 26px、Chat 欢迎语 30px），靠字号而不是加粗拉层级。
5. 输入框聚焦改为浅绿描边加柔光，不再是蓝框。

涉及：`tokens.css`、`style.css` 末尾覆盖段、`src/studio-home.css`、`src/chat-workbench.css`、`src/styles.css`。截图：`.codex/redesign/soft-*.png`，对照 `base-*.png`。

## 第 2 步（第一部分）：浅色摄影棚视觉 + 画布左侧素材栏

### 为什么

原来用近黑底配单一亮色，所有内容都做成一样的圆角卡片，模板感重；产品图（尤其绿色系）放在近黑底上颜色失真。新方向是：画布用中性灰底，方便判断产品颜色；四周的界面用纸面色，文字用墨黑；强调色只用在"选中、已采用、生成中"这几种状态上。

### 怎么改的

1. **设计变量**（`frontend/public/studio/tokens.css`）重写为浅色一套。新增 `--ui-stage`（画布灰 #8f8f8c）、`--ui-shadow`、`--ui-success`、`--ui-danger`、`--font-num`。强调色从浅蓝 #b7cbe4 改成深蓝 #2f5d8a。字体优先用 HarmonyOS Sans SC / MiSans，没有就回落到微软雅黑。Chat、项目页、画布都用这一套变量。
2. **写死颜色的批量转换**（`scripts/relight_css.py`，一次性脚本）。旧 CSS 里有近 900 处写死的颜色，逐个手改不现实，所以按规则转换：
   - 灰色类（中性色）：反转明度，偏暖一点。深色背景变纸面色，浅色文字变墨色。
   - 饱和色：色相不变，浅色变中深、深色变浅底，保证在纸面上读得清。
   - 黑色半透明保留为阴影；白色半透明改成墨色半透明（用于悬停底色）。
   - 涉及 10 个 CSS 文件：`style.css` 和 `src/` 下 9 个，共 897 处。
   - 转换前的原文件备份在 `.codex/redesign/css-backup-step2/`。
3. **画布覆盖样式**（`style.css` 末尾的 "Redesign step 2" 段）：
   - 画布灰底加点阵。
   - 节点标题用浅色字，压在灰底上。
   - 图片和备注卡片加阴影，不再用描边。
   - 选中只用强调色描边。
   - 连线改为半透明白色。
   - 底部工具条为纸面色，"+" 按钮为墨色。
   - 顶栏当前页签用下划线标示。
4. **左侧素材栏**（`index.html` 的 `.library-rail`，逻辑在 `app.js`）：
   - 展开宽 248px，收起 44px，画布随之让出位置。素材栏不在画布坐标系里，所以节点坐标不受影响。
   - 可以搜索，点缩略图会先调用 `/library/{obj}/use` 给当前项目授权，再放进画布。
   - 原来"上传图片后摆放节点"的逻辑抽成了 `placeAsset()`，上传和素材库两条路径共用。
5. **选中图片节点的工具条**加了"收进素材库"按钮，调用 `POST /api/workspaces/{ws}/library`。
6. Chat 侧栏的品牌图标改为墨色，原来的浅灰色在纸面上看不清。

| `project_archive(workspace, archived_at)` | 有记录即已归档。单独建表而不是改 `video_workspaces`，因为后者整行是 JSON，归档不应改项目修订号。 |
| `library_items(object_id, name, kind, source_workspace, created_at)` | 素材库条目，`object_id` 指向 `file_objects`，不复制文件。 |

素材库里的文件额外写一条 `media_grants(scope='library', object_id)`；某个项目使用素材库文件时，再给该项目写一条授权，原有的 `/studio/media/objects/{id}` 权限检查无需改动。

`media_storage.migrate_schema`：
- 迁移列表加入版本 3。
- 原来只有版本 2 会在迁移前自动备份，现改为版本 2 及以后都备份到 `.hermes/backups/schema-v{版本}-{时间}.sqlite3`。

已用真实库副本验证：迁移后 23 个项目仍在，自动生成了 `schema-v3-*.sqlite3` 备份。

### 后端接口（`miniclaw_web/studio.py`，逻辑在 `studio_projects.py`）

| 接口 | 作用 |
| --- | --- |
| `GET /api/workspaces?archived=true` | 列出已归档项目；默认列表排除已归档 |
| `POST /api/workspaces/{ws}/archive` `{archived, collect?}` | 归档 / 恢复；`collect:true` 时先把项目里已保存的图片收进素材库 |
| `GET /api/workspaces/library?q=` | 素材库列表（最多 500 条） |
| `POST /api/workspaces/{ws}/library` `{file, name}` | 把一个项目文件收进素材库，文件必须已授权给该项目 |
| `POST /api/workspaces/{ws}/library/{obj}/use` | 把素材库文件授权给某项目，返回可在画布引用的地址 |
| `POST /api/workspaces/library/{obj}/remove` | 移出素材库（文件本身保留，项目里的引用不受影响） |

素材库路由注册在 `/api/workspaces/{workspace}` 之前，避免 `library` 被当成项目 id。移出用 POST 而不是 DELETE，是为了沿用现有 `writeApi` 的会话令牌和同源检查。

归档只是隐藏，项目数据、修订号、Chat 关联都不变，随时可恢复。没有保存到 `file_objects` 的旧文件（例如 `macro.png` 这种早期相对路径）不会进素材库，归档提示里的数量只计实际收进的。
